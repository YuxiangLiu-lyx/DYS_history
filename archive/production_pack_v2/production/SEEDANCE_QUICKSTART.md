# 第一回《风起徽州》：用现有材料制作 Seedance 视频

核查日期：2026-09-22。成片保持锁定的 **90 秒、7 个 Scene Block、24 个叙事镜头＋片尾标题**。本流程只说明制作方法，不表示已经生成、试听或验收过视频。角色和关键帧使用本轮 `refs_upload.json` 指向的版本，禁止从旧聊天重新生成人物。

**1．下载整份仓库，先打开这三份文件。**

从 [DYS_history](https://github.com/YuxiangLiu-lyx/DYS_history) 下载或拉取最新提交，完整保留目录；所有下列路径都从仓库根目录计算。

| 文件 | 你用它做什么 |
|---|---|
| [context/STATUS.json](../../../context/STATUS.json) | 查看哪些素材已完成、哪些仍待审阅，以及实际同步状态。 |
| [VIDEO_PRODUCTION_PACK.md](VIDEO_PRODUCTION_PACK.md) | 查每场画面、对白、动作、声音和连续性。 |
| [refs_upload.json](refs_upload.json) | 查每个任务的图片上传顺序及完整文件名；这是素材选择单。 |

完整 Prompt 已拆好，位于 `episodes/ep01/production/prompts/`。`A_PROMPT.txt` 对应 A，依此类推；结尾优先用 `G20_PROMPT.txt` 至 `G24_PROMPT.txt`，而不是把五个地点一次交给模型。人物多角度拼板仅供审阅，上传时用清单里的独立图片。

先看当前潘慧正脸和近景：小痣应在**嘴角下方的皮肤上**，不能落在唇缘、嘴角横向延长处或变成唇彩；位置、大小和方向与本轮正脸母版一致，不能镜像。她的妩媚来自温柔而有神的眼睛、放松的嘴角与自然神态；不能为“媚劲”重新捏脸、过度磨皮或增加未写入剧本的挑逗动作。小腿使用本轮生成并列入清单的历史化母版，用户提供的表情图不直接承担视频里的发型和服装设计。

**2．在官方入口选模型、模式和时长。**

打开 [即梦视频入口](https://jimeng.jianying.com/ai-tool/home?type=video)，进入视频生成，核对当前选择的实际模型，选择账号可用的 **Seedance 2.0** 和 **全能参考／多模态参考**。不要以为进入网页后默认模型、比例和片长就已正确；如果显示 mini、Fast 或其他版本，把实际版本记录下来，并先验证一段再批量制作。

本项目画幅设 **16:9**。先用账号支持的标准清晰度验证动作、脸和对白，合格后再做最终清晰度；本流程不保证所有入口都提供同一分辨率。官方模型材料支持 4–15 秒输出及图／视频／音频参考，网页里可选的具体片长、素材总数和收费仍以该账号显示为准。[官方模型说明](https://arxiv.org/abs/2604.14148)

| 任务 | 生成目标 | 剪映放入总时间线 |
|---|---:|---|
| A 官仓 | 13 秒 | 00–13 秒 |
| B 私仓 | 11 秒 | 13–24 秒 |
| C 皇城／上朝 | 10 秒 | 24–34 秒 |
| D 奏报 | 13 秒 | 34–47 秒 |
| E 听松楼 | 15 秒 | 47–62 秒 |
| F 夜窗问答 | 13 秒 | 62–75 秒 |
| G20／21／22／23／24 | 各生成 5 秒源视频，按第 5 步剪取 | 合成 75–87.5 秒 |
| 标题 | 剪映制作 2.5 秒 | 87.5–90 秒 |

若入口不能直接选 11／13 秒，就选不短于目标的可用片长，增加结尾自然停留余量，保存这份实际使用的 Prompt；剪辑仍保留原定长度。不要把 90 秒故事整体加速，或把超长的对白硬截掉。

官方要求真人人像主体参考完成本人验证或取得相应授权；火山方舟另有可信素材库接入。**本项目的图片存在，不代表账号已完成该接入。**若提交时出现此要求，按该入口正常流程办理；不要通过换名字或古装化图片绕过。我们尚未替你验证账号的真人素材接入、生成效果或费用。[官方说明](https://seed.bytedance.com/zh/blog/official-launch-of-seedance-2-0) · [可信素材库](https://www.volcengine.com/docs/82379/2315856)

**3．先做 A 验证动作，再做 F 检查潘慧表演；每次只提交一个任务。**

以 A 为例，按照以下顺序添加图片，再把 `A_PROMPT.txt` 全文复制进输入框。

| 标签 | 上传文件 |
|---|---|
| `@图片1` | `assets/scenes/S01_DAY_v01.png` |
| `@图片2` | `assets/characters/E02/E02_ELDER_v01.png` |
| `@图片3` | `assets/characters/E01/E01_GUARD_v01.png` |
| `@图片4` | `assets/characters/E03/E03_CHILD_v02.png` |
| `@图片5` | `assets/characters/E08/E08_VILLAGER_v01.png` |
| `@图片6` | `assets/keyframes/A/A_IN_v02.png` |
| `@图片7` | `assets/keyframes/A/A_OUT_v01.png` |

**输入 `@` 后，选择界面里实际上传的那份素材。**网页显示的标签可能带空格或采用文件名；逐一把 Prompt 中的 `@图片N` 对应到真实素材，不要只粘贴七个没有绑定素材的普通文本标签。未上传视频时，不新增 `@视频1`。

A 的通过标准：0–3 秒看见官仓与队伍；3–8 秒老人递碗、官差推同一侧上臂；8–13 秒老人跌坐、碗滚到孩子旁、孩子蹲下扶人。逐字核对三句原对白，尤其检查动作能否从前镜接到后镜。手、碗或接触关系明显错误，先修对应动作段；背景远处的小瑕疵不必整段重抽。

F 使用 `refs_upload.json` 中 **job=F** 的七个 `slots`，当前人物版本和关键帧可能继续递增，因此以清单里的 `file` 字段取图，不凭记忆选旧图：

| 标签 | 对应素材和用途 |
|---|---|
| `@图片1` | 潘慧当前正脸：五官、嘴角下方的小痣、玉簪方向。 |
| `@图片2` | 潘慧当前夜间披帛版：只定义披好后的状态。 |
| `@图片3` | E06 侍女独立图。 |
| `@图片4` | S06 楼上私室夜景。 |
| `@图片5` | F_IN 当前版：开场尚未披帛。 |
| `@图片6` | F_OUT 当前版：已披帛、回答后转回窗边。 |
| `@图片7` | 潘慧当前基础全身版：同一衣服和体态。 |

复制 `F_PROMPT.txt`，设 13 秒。检查侍女确实放灯并披帛、潘慧听完问题后才回答、近景里痣位不漂移、笑意柔和而有吸引力。对白仍是“小姐想嫁什么样的人？”“我也不知道。”“总得先见着那个人。”不要因模型漏词自行改剧本。

这里的 `IN／OUT` 图在全能参考中是**构图与动作状态参考**，不是逐像素保证的首尾帧。只有当前入口明确提供专用首／尾帧功能时才使用对应槽；不要假定它能与全能参考、视频延长全部同时开启。模型未精确踩到分镜秒点时，按生产包剪辑；大幅偏离动作或台词则重做对应镜段。

**4．做其余片段，并用已验收视频接续需要连续的场面。**

A、F 通过后做 B、C、E；有了 C 再做 D；A–F 的可用版本确定后做 G 的五个子作业。各任务按 `refs_upload.json` 上图，再复制同名 Prompt。参考视频用**已采用画面的局部时间**取段，不能把计划关键帧当作模型实际输出。

| 后续任务 | 取哪段已验收的视频 | 只继承什么 |
|---|---|---|
| D | C 局部 6–10 秒 | 皇帝衣冠、御座光线与殿内尺度；D 仍按自己的机位开场。 |
| G20 | D 局部 0–5 秒，可选 | 小腿脸和衣服；夜光、偏室由 G20 自己的图决定。 |
| G21 | A 局部 8–13 秒，可选 | 老人孩子和官仓尺度；不继承白天降雨。 |
| G22 | B 局部 4–8 秒，可选 | 魏笑和案边道具；不继承白日光。 |
| G23 | C 局部 3–10 秒，可选 | 皇帝和西卡的衣冠体态；不继承朝堂室内。 |
| G24 | **F 局部 9–13 秒＋实际最后可见帧**，优先 | 同一夜窗、已披好的披帛、灯光、朝向和动作。 |

A→B、B→C、D→E 是换地点；E→F 是楼上夜戏。无需强行上传上一块尾帧，否则容易把错误的光线、场所带入下一场。F 通常不需要 E 视频；仅材质偏离时才按清单引用 E 局部 0–3 秒，并说明只取衣服、发髻和木材质感。

将 F 已采用的完整 13 秒画面保存为 `F_accepted.mp4`，取局部 9–13 秒保存为 `F_ref_09-13.mp4`，从**这段实际视频**取最后一个可见画面保存为 `F_LAST.png`；上传到 G24 的 `@视频1` 和可选 `@图片5`。若需要命令行取素材，可让执行 AI 运行：

```bash
ffmpeg -i F_accepted.mp4 -ss 9 -t 4 -map 0:v:0 -an -c:v libx264 -crf 18 -pix_fmt yuv420p F_ref_09-13.mp4
ffmpeg -sseof -1 -i F_accepted.mp4 -an -fps_mode passthrough -update 1 F_LAST.png
```

第二条从结尾解码并持续覆盖同一 PNG，留下实际最后一帧；打开确认没有黑屏或故障帧。没有可靠尾帧时选取最后稳定可见帧，并记下其真实时间。支持视频延长的入口也可延长 F，再把新增的 3 秒放到 **84.5–87.5 秒**；不能直接接在 F 后面而删掉中间四镜。

**5．在剪映按锁定时间线剪成 90 秒，再完成声音。**

新建 16:9 项目，以 24fps 的锁定时间线为准；导入原始视频、`audio/dialogue_timing.srt` 和 `audio/dialogue_cues.csv`（均在 `episodes/ep01/production/` 内）。CSV 是配音/核对表，不是已有录音；SRT 是预定时间，需要与最终采用音轨一起核对。

G 的五段 5 秒源视频按下面区间选取；合计画面 12.5 秒，加片尾标题 2.5 秒，就是 G 的 15 秒。

| 源任务 | 源视频保留区间 | 成片位置 |
|---|---|---|
| G20 | 0.5–4.0 秒 | 75–78.5 秒 |
| G21 | 1.5–3.0 秒 | 78.5–80 秒 |
| G22 | 1.5–3.0 秒 | 80–81.5 秒 |
| G23 | 1.0–4.0 秒 | 81.5–84.5 秒 |
| G24 | 1.0–4.0 秒 | 84.5–87.5 秒 |
| 剪映标题 | 2.5 秒 | 87.5–90 秒 |

这些是 Prompt 预留的选段窗口，实际动作若稍有偏移，可以在源视频中移动选区，但保留时长与动作必须相同，并记录新入出点。不要用明显快放把一个慢动作硬挤进 1.5 秒。

最容易剪错的是 **C／D 的小腿奏报**：完整一句“徽州粮价平稳，百姓安居乐业。”在总时间 **33.6–38.1 秒**连续播放，C 的最后 0.4 秒先听见声音，D 开头已经在说话。使用同一条完整配音跨两块铺设，34 秒处不得重说开头。若使用原生生成音轨，也要保证其连续性、逐字准确和可用口型，不能把两份独立生成的整句直接拼在一起。

46.7 秒先入琴声，47 秒见听松楼；74.8 秒先入纸声，75 秒见密报；史官整条旁白放 78.7–87.3 秒，跨镜播放。对白、环境声、拟音、BGM 分轨混音；模型的视频声音不等于自动提供了可分离音轨。人声压过音乐，角色音色稳定，片尾文字用 `title_card.svg` 或在剪映重建，别让模型临时造字。

最终逐项看一遍：真人神似与痣位、衣服和披帛、手部接触、正反打轴线、口型与漏字、帝潘没有相遇、皇帝仍不知灾情、90 秒总长。主片保留严肃历史剧表演；简介注明 AI 生成／架空历史二创。只有关键错误需要重抽，对不影响观看的轻微瑕疵直接采用。

**6．每完成一段，就保存原片、实际 Prompt 和剪辑选择，再同步 GitHub。**

建议每次生成用独立目录，例如 `episodes/ep01/video/A/take_001/`，至少包含 `output_original.mp4`、`prompt_used.txt`、`record.json`；引用片段、实际尾帧和采用成片也放同一目录或记录明确相对路径。记录实际模型/入口、设置、输入素材路径与版本、任务ID、费用（未知填 null）、采用理由、源视频入出点和放入成片的位置。

例如 G24 采用记录应准确写出：来源是哪个 F take，参考其局部 9–13 秒，尾帧实际取自几秒，G24 的哪 3 秒放到 84.5–87.5 秒。Prompt 改了一个字也保存实际提交版，不能只留下模板或“见聊天”。

音频原文件、分轨、字幕、剪映工程及其素材、最终导出一并保存；更新 `context/STATUS.json` 和 `history/CHANGELOG.md`，运行仓库校验脚本后正常 commit/push，再核对远端提交。大视频按仓库确定的 LFS／Release 策略保存原文件与校验和，不只留下会过期的下载链接。这样下一位 AI 读 `AGENTS.md` 就能继续已有镜头，不需要重新生成。
